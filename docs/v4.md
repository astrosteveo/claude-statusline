# claude-statusline 4

## Problem

Version 3 made the bar look good, configurable live, and a game. Game mode
(`[quest] placement = "game"`) became the favourite way to run it, and it is
where version 3 falls short:

- Game mode replaces your lines with the quest ticker and the scene, so the
  model, directory, git, PR and cost vanish. At 220 columns the ticker row
  had 73 blank columns while the news stopped at a fixed 48-character cap.
- The gauges beside the scene are the compact `ctx 28%` at every width, so a
  wide terminal loses the reset countdowns and pace projections the normal
  bar shows.
- The catalog is closed. People who want one number of their own on the bar
  (the on-call engineer, a deploy's state, a Kubernetes context) have no way
  to get it, because a command in a segment would run on every refresh.
- The game ignores most of what Claude Code does now: subagents come and
  go, conversations compact, and the scene shows none of it.

## What 4 is

Version 3's engine and guarantees (never blank, never too wide, about 10 ms
a refresh), plus:

1. **Session details in game mode's top row.** The model first, then the
   segments of your own lines, in the room the game sections leave. Details
   give up detail first and drop last; the game sections render exactly as
   they would without them. On wide terminals the gauges beside the scene
   show bars, pace and reset times too.
2. **Command segments.** `type = "command"` shows the first line of your own
   command's output. The command runs in a detached background process, at
   most every `every` seconds, killed after `timeout`, and the bar only ever
   reads its cached output. `[commands] enabled = false` turns every one off.
3. **Lines by width.** `min_width` and `max_width` on a `[[line]]` show it only
   on terminals that wide, so a narrow split can use one line and a wide
   window three.
4. **A cache countdown.** The `cache` segment counts down the last minutes of
   a warm prompt cache (`prompt_cache.expires_at`) and names the cause of the
   last miss (`last_miss_cause`), both new in the payload since version 3.
5. **Claude Quest: the party.** Subagents join your pet in the scene while
   they work (SubagentStart and SubagentStop), and the game reacts to
   compaction (PreCompact and PostCompact). Each is news, XP, and an
   achievement or two.
6. **Claude Quest: Halloween and rare events.** From 24 October to 1 November
   bosses are haunted, seasonal loot and a set drop, and the scene has
   pumpkins and bats. A rare treasure goblin can show up any day.
7. **`statusline.py demo`.** A scripted session played in your terminal: the
   bar under a conversation, through themes, styles, narrowing and game mode.
   The trailer is built from the same script.

## What done means

Every feature has tests in the suite's style (property sweeps for the engine,
unit tests for game rules), a README section, entries in the skill's
reference files and the generated catalog, its settings in the configurator,
and a beat in the trailer if it shows on the bar.

1. **Top row.** `[quest] game_details` is `"auto"` (the default) or a list.
   Auto is `model`, then every segment of your lines (or your preset's) in
   order, leaving out quest segments and whatever the gauges show. A test
   sweeps 40 to 300 columns, all 8 styles and 4 icon sets, the quiet, busy
   and hot samples, and Quest states with a boss, a raid, a dungeon, buffs
   and fresh news, and finds the game sections' spans identical with and
   without details. At 220 columns, with a copy of the user's config and
   the busy sample and no news, the row shows the model with its effort, the
   directory, git, the PR and the cost. `validate` checks the key, `doctor`
   lists the game rows, `preview` notes say what gave way (game sections,
   news, details), and the configurator edits the details and gauges on its
   Layout page when game mode is on.
2. **Command segments.** A refresh never runs a command and never waits for
   one: tests prove a stale entry starts one detached runner (a lock keeps it
   to one), a slow command is killed at `timeout`, output keeps its SGR
   colours and loses every other control sequence, the off switch hides the
   segments and starts nothing, and previews run the command once, bounded
   by the timeout. `doctor` lists each command's last run, duration and exit
   status. Commands are read only from your own config file.
3. **Lines by width.** A line outside its bounds is left out; `preview` says
   so; `validate` checks the bounds; the Layout page sets them per line.
4. **Cache countdown.** With a warm cache inside its last `countdown` minutes
   the segment shows the time left; a low hit ratio shows the miss cause.
5. **The party.** `quest enable` registers the four new hooks, and `doctor`
   and `quest status` say when an older registration lacks them. The save
   keeps the party (members expire on their own if a stop never arrives).
   The text scene draws companions following the pet; the kitty scene draws
   them into its frames, and keeps showing the previous picture until the
   new one has been uploaded, so a change never blanks the scene.
6. **Halloween and rare events.** Season dates, loot tables, bosses and the
   goblin are unit-tested with fixed clocks; saves from every version load;
   `[quest] seasons = false` turns seasons off; both scenes are decorated.
7. **demo.** Plays in any terminal at least 60 columns wide, `q` quits, and a
   test renders every step of the script within the width budget.

Performance: `statusline.py bench` stays within 1 ms of version 3's median
(9.7 ms with the default config, 10.2 ms with game mode on this machine), and
the refresh path still imports none of `json`, `re`, `tomllib` or
`subprocess`.

## Key decisions

- **Two passes on the top row.** The game sections are fitted alone, exactly
  as in version 3; the news then grows into the spare room; the session
  details get what is left and are placed right-aligned against the streak
  and gold. Nothing the details do can reach back into the game sections,
  which is what makes "identical with and without" provable.
- **Details have one more level than lines.** After `text` comes `glance`:
  segments whose icon colour carries their state (git, PR, cache, vim, the
  gauges) shrink to that icon; the rest keep their text. Only then do details
  drop, lowest priority first. Ordinary lines keep version 3's five levels.
- **The gauge column's width depends on the terminal, not the values.** A
  countdown ticking from `1h00m` to `59m` must not resize the scene, since a
  new scene width means a new kitty picture.
- **Commands follow git's pattern.** Stale-while-revalidate in the runtime
  directory, a lock per command, a detached runner. The runner does all the
  parsing (colours into styled runs), so a refresh reads one marshal file.
- **The scene switches only to pictures kitty already has.** The uploader
  writes a ready mark after its last frame; until then the bar keeps naming
  the previous picture.
- **Seasons are data.** A season is dates plus boss names, loot, a quest and
  scene props, so the next one is a table, not code.

## Rejected

- **Live tool activity from hooks** (the tool running now, turn timers).
  Claude Code already shows the running tool, its elapsed time and the
  subagents panel right above the bar; repeating them costs two hook
  processes per tool call for information already on screen. The party uses
  the subagent events for the game instead.
- **Todo progress.** The task tools are off by default on current models, so
  the segment would be empty for most people.
- **A per-project config.** Useful, but a repository could then set commands
  to run; it needs its own trust model and is left for later.
- **A terminal-palette theme.** The `terminal` theme already follows the
  terminal's 16 colours.
- **Rendering the boss's HP into the kitty picture.** Every hit would be a new
  picture to upload; the hearts stay on the top row.
